# llm-t4-lab

![tests](https://github.com/crptptn/llm-t4-lab/actions/workflows/tests.yml/badge.svg)

Практика с LLM на бесплатных GPU Kaggle (2× NVIDIA T4 по 16 ГБ): как ведёт себя vLLM под нагрузкой, что дают квантизация и QLoRA, как измерить качество RAG и вызова инструментов. Все цифры в [RESULTS.md](RESULTS.md) пишут сами скрипты, руками там ничего не правится.

Модели — Qwen2.5-Instruct (1.5B, 3B и 7B-AWQ): помещаются на T4 и нормально понимают русский.

## Эксперименты

### 1. Бенчмарк vLLM — `lab/bench.py`

Поднимаю `vllm serve` с OpenAI-совместимым API и гоняю стриминговые запросы при 1, 2, 4 … 64 одновременных. На каждом уровне считаю:

- **TTFT** — время до первого токена. В основном это prefill и ожидание в очереди, растёт с конкурентностью;
- **TPOT** — время на каждый следующий токен, то есть скорость декодирования для одного пользователя;
- **throughput** — выходные токены в секунду по всей пачке. Растёт за счёт continuous batching, пока GPU не упрётся в память или вычисления.

Длина ответа фиксирована (`ignore_eos`, 256 токенов), иначе уровни нельзя сравнивать. Токены считаются по `usage` из последнего чанка, а не по числу чанков.

Отдельный сценарий — **prefix caching**: у всех запросов общий системный промпт примерно на 2 тыс. токенов. Прогоняю его с кэшем и без и сравниваю TTFT. Когда префикс уже лежит в KV-кэше, prefill почти не нужен.

### 2. Квантизация — `lab/quant.py`

Qwen2.5-3B в FP16, AWQ и GPTQ (4 бита) на одних и тех же задачах GSM8K: размер весов, скорость в пакетном режиме и в один поток, точность. Каждый вариант запускается в отдельном процессе, чтобы память GPU гарантированно освобождалась между моделями. Ответы со всеми ошибками сохраняются для разбора.

### 3. Классификатор обращений граждан на QLoRA — `lab/appeals/`

Задача: отнести обращение к одной из 8 категорий (ЖКХ, дороги и транспорт, благоустройство, здравоохранение, образование, социальная поддержка, экология, цифровые госуслуги).

- **Данные** (`generate.py`). Реальные обращения содержат персональные данные, поэтому датасет синтетический, его генерирует Qwen2.5-7B. Чтобы тест не повторял трейн по форме, у теста свои стили (пост в городском паблике, сбивчивое письмо пожилого человека), которых в обучении нет. Дубликаты убираются в том числе между выборками. Можно подставить свой CSV с колонками `text,label`.
- **Обучение** (`train.py`). Qwen2.5-1.5B в 4 битах (NF4, двойная квантизация), LoRA r=16 во всех линейных слоях. Loss считается только по названию категории, промпт замаскирован. На T4 нет bf16, поэтому fp16 и paged AdamW 8-bit.
- **Оценка** (`evaluate.py`). Адаптер раздаётся тем же vLLM-сервером (`--enable-lora`), что и базовая модель. Сравниваю три режима: база со свободным ответом, база с ответом, ограниченным JSON-схемой (так видно, какая часть ошибок — просто неверный формат), и база с адаптером. Метрики: accuracy, macro-F1, F1 по классам, матрица ошибок.

### 4. RAG на SberQuAD — `lab/retrieval.py`, `lab/rag_eval.py`

Корпус — около 10 тыс. уникальных абзацев SberQuAD, запросы — вопросы из validation. Для каждого вопроса известен абзац с ответом, поэтому качество поиска считается без ручной разметки.

- **Поиск.** BM25 со стеммером Snowball (своя реализация на разреженной матрице, проверена тестом против формулы), плотный поиск multilingual-e5 + FAISS, гибрид через Reciprocal Rank Fusion, переранжирование top-20 cross-encoder'ом bge-reranker-v2-m3. Метрики: recall@1/3/5/10, MRR@10, задержка на запрос.
- **Faithfulness.** Модель отвечает по top-3 абзацам, затем LLM-судья разбивает ответ на утверждения и проверяет каждое по контексту. Метрики считаются отдельно для случаев, когда нужный абзац нашёлся и когда нет: так видно, отказывается ли модель отвечать или начинает выдумывать.

### 5. Function calling и structured output — `lab/tools_eval.py`

Ассистент портала обращений с четырьмя инструментами (статус обращения, новое обращение, поиск МФЦ, долг по ЖКУ) и 26 тест-кейсов в [data/tools_cases.json](data/tools_cases.json). 8 кейсов из 26 — негативные: болтовня без запроса действия или нехватка данных (нет номера обращения, лицевой счёт из 5 цифр вместо 10), нужно переспросить, а не выдумывать аргументы. Проверяется выбор инструмента, значения аргументов, валидность JSON и соответствие схеме (`jsonschema`).

Structured output: извлечение полей из обращения просто по инструкции и через `response_format=json_schema`. Сравнивается доля ответов, которые парсятся как JSON и проходят схему.

## Как запустить

**Kaggle.** Импортировать [notebooks/kaggle.ipynb](notebooks/kaggle.ipynb), в настройках выбрать *GPU T4 x2* и включить интернет. Ноутбук ставит зависимости, по очереди поднимает нужные серверы и в конце собирает `results.zip`. Его содержимое кладётся в репозиторий, а `RESULTS.md` пересобирается командой `python -m lab.report`. Разделы независимы, их можно запускать по одному.

**Отдельные шаги** (на машине с GPU):

```bash
pip install -r requirements.txt

python -m lab.server start Qwen/Qwen2.5-1.5B-Instruct -- --enable-prefix-caching
python -m lab.bench --model Qwen/Qwen2.5-1.5B-Instruct --scenario shared-prefix --tag prefix_on
python -m lab.server stop

python -m lab.quant --n 300
python -m lab.rag_eval retrieval --n-queries 1000
python -m lab.report
```

**Тесты** — без GPU, за несколько секунд:

```bash
pip install -r requirements-dev.txt
ruff check . && pytest -q
```

Тесты проверяют метрики и разбор ответов, BM25 и RRF, маскирование промпта при обучении, сами тест-кейсы инструментов и клиентскую часть бенчмарка и оценок. Для последнего в `tests/conftest.py` поднимается фейковый OpenAI-совместимый сервер со стримингом, tool calls и ошибками 500. Тесты гоняются в GitHub Actions на каждый push.

## Структура

```
lab/
  server.py        запуск vLLM в фоне (start / stop / log)
  bench.py         TTFT, TPOT, throughput, prefix caching
  quant.py         FP16 / AWQ / GPTQ на GSM8K
  appeals/         синтетика → QLoRA → оценка через vLLM с LoRA
  retrieval.py     BM25, e5 + FAISS, RRF, reranker
  rag_eval.py      recall@k, MRR, faithfulness
  tools_eval.py    function calling, structured output
  metrics.py       метрики и парсинг ответов
  report.py        results/*.json → RESULTS.md
data/              тест-кейсы инструментов, сгенерированные обращения
results/           JSON с результатами прогонов (коммитятся)
tests/             pytest, без GPU
```

## Ограничения

- T4 — это Turing: нет bf16 и FlashAttention 2, поэтому везде `--dtype half`, а vLLM сам берёт Triton-реализацию attention. Абсолютные цифры скорости на A100/H100 будут другими, сравнивать стоит только варианты между собой.
- Обращения синтетические. Тест в других стилях снижает утечку, но оценка всё равно оптимистичнее, чем на реальных данных.
- Faithfulness считает LLM-судья. Модель 7B иногда ошибается в разбиении на утверждения, поэтому в результатах сохранены примеры с низкой оценкой — их стоит просмотреть глазами.
- Выборки небольшие (300 задач GSM8K, 1000 вопросов SberQuAD), различия в пару процентов — в пределах шума.
